# Parking Counter: live vehicle counting in the browser

A landing page and a live counter app. Point any camera at a road, draw a line or a zone, and Parking Counter counts cars, trucks, buses, motorcycles, bicycles and people in real time.

**Everything runs on the visitor's device.** Video never leaves the browser, there is no backend, and the site deploys to Vercel as static pages.

## Tech stack

| Layer | Technology |
|---|---|
| Framework | **Next.js 16** (App Router, TypeScript), deployed on **Vercel** |
| Computer vision | **OpenCV.js** for image prep (`cvtColor`, `resize`, `copyMakeBorder` letterbox, `blobFromImage`) and the zone test (`pointPolygonTest`) |
| Object detection | **YOLO11n** (ONNX) on **ONNX Runtime Web**: **WebGPU** on the GPU, with a WebAssembly fallback on the CPU |
| Tracking & counting | TypeScript IoU + distance tracker, line crossing (IN/OUT) and zone occupancy |

## How it works

```
camera / video ─► OpenCV.js ─► YOLO11 (ONNX Runtime Web) ─► NMS ─► tracker ─► line + zone counts
                  letterbox     WebGPU or WebAssembly                  IDs       dashboard
```

1. Each video frame is drawn to a canvas, shrunk to 640 px and read by OpenCV.js.
2. OpenCV.js letterboxes it to 640×640 and builds the model input with `cv.blobFromImage`.
3. ONNX Runtime Web runs YOLO11 and returns 8,400 candidate boxes. Boxes below the confidence threshold and duplicates are removed (NMS).
4. The tracker gives each object a stable ID. An object is counted once when its path crosses the line. `cv.pointPolygonTest` checks whether it is inside the zone.
5. The canvas draws boxes, trails, the line and the zone every screen refresh, and the dashboard updates live.

Measured in Microsoft Edge on a laptop with Intel integrated graphics: the detector is ready in about 9 s on the first visit, then runs at **about 11–12 FPS on WebGPU**. The CPU fallback is about 360 ms per frame.

```
src/
├── app/

    ├── runtime.ts               loads OpenCV.js and ONNX Runtime Web on demand
    ├── detector.ts              OpenCV.js pre-processing + YOLO11 inference + NMS
    ├── tracker.ts               tracker, line counter, zone counter
    └── types.ts

```

`public/vendor/` is generated by `scripts/copy-vendor.mjs` and is not committed.

## Scroll-driven video hero (optional)

The landing page can open with a full-screen video that plays as you scroll, with YOLO11 detection boxes drawn on the vehicles and text chapters that fade in and out. This is the same technique Apple uses for its product pages.

1. Use footage **you own or have a licence for**. It will be published on your site. A 5–15 second clip of a road, car park or garage works well, in landscape or portrait.
2. Generate the frame sequence. OpenCV extracts the frames and runs YOLO11 on each one:
   ```bash
   pip install opencv-python numpy
   python tools/make_scroll_sequence.py path/to/video.mp4            # 120 frames by default
   python tools/make_scroll_sequence.py clip.mp4 --frames 160 --quality 70
   ```
   This writes `public/scroll/frame_000.webp …` plus `public/scroll/manifest.json` (about 5–15 MB).
3. Commit `public/scroll/` and deploy. The page detects the sequence at build time and shows the scroll story as the hero. The tablet dashboard then follows it as the next section. Delete the folder to go back to the tablet hero.

Portrait (phone) videos are shown whole over a blurred copy of themselves on wide screens, and full-bleed on phones.

## Run locally

```bash
npm install
npm run dev
```

Open http://localhost:3000. Camera access works on `localhost` and on any `https://` site.

## Deploy to Vercel

**Option A: GitHub (recommended)**
1. Push this folder to a GitHub repository.
2. On vercel.com, click **Add New → Project** and import the repository. The framework is detected as **Next.js**, so no settings need changing.
3. Click **Deploy**. Your site will be live at `https://<project>.vercel.app`.

**Option B: Vercel CLI**
```bash
npm i -g vercel
vercel          # preview deployment
vercel --prod   # production
```

`next.config.ts` sets `Cross-Origin-Opener-Policy` and `Cross-Origin-Embedder-Policy` headers. These let ONNX Runtime use multi-threaded WebAssembly on devices without WebGPU, and Vercel applies them automatically.

## Notes and limitations

- Speed depends on the visitor's device. Browsers with WebGPU (recent Chrome and Edge) are much faster than the CPU fallback.
- The first visit downloads about 55 MB (OpenCV.js 13 MB, ONNX Runtime 29 MB, model 11 MB). After that, the browser caches everything.
- An object hidden behind another while it crosses the line can be missed. An object that leaves the frame and returns gets a new ID.
- Recorded videos must use a codec the browser can play, such as H.264 MP4 or WebM.
